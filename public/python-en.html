Python in glpython

How it differs from CPython, the Python from python.org.

glpython runs Python 3.12 in the browser, with Pyodide 0.26: that is CPython, compiled to WebAssembly. The language and the standard library are the same. What differs is what a browser can't do, and a few things glpython adds. For the language itself: the Python tutorial and the language reference.

Files

  • The project's files are in the folder /, e.g. /main.py. import helper finds helper.py.
  • The working directory, though, is /home/pyodide: open("data.txt") doesn't find a file of the project, open("/data.txt") does.
  • What a program writes to a file stays in memory only, until Python restarts (Stop, «Restart Python», reloading the page). It doesn't appear in the editor and isn't saved. If a program writes to a file of the project, the next ▶ uses the text from the editor again.
  • ▶ runs the project's main file; the console names it.

What the browser lacks

  • No network: urllib.request doesn't know https, a connection with socket times out.
  • No threads or processes: threading.Thread(…).start() raises RuntimeError; subprocess, multiprocessing and os.fork() raise OSError.
  • Only the standard library: there is no pip; packages such as numpy or requests are missing. Missing from the standard library: tkinter, turtle, sqlite3, ssl, lzma, curses, readline, dbm, venv, ensurepip and idlelib.
  • asyncio.run() doesn't work («cannot be called from a running event loop»), nor does webbrowser.

Input and output

  • input() asks in the console: the >>> line becomes the input line. That works only where the page can wait for an answer: always in the IDE, often not in an embedded editor (e.g. in a course). There input() ends with RuntimeError: input() is not available here, and help(), breakpoint() and sys.stdin don't work either. Stop while the program waits raises EOFError, as Ctrl+D does.
  • Output appears line by line: text without a line end (print(…, end="")) only with the next line. Blank lines and spaces at the start and end of the output are dropped (at the start only when the program ends without an error). sys.stdout and sys.stderr appear together in the console.
  • time.sleep() really waits; what was printed before is already there.
  • sys.exit() and exit() end the program, but with SystemExit in the console; CPython ends it silently.
  • Stop ends an endless loop. Stop ends Python altogether, without KeyboardInterrupt: afterwards the input line knows nothing from before.

One Python for the whole session

  • CPython starts afresh for every python main.py. glpython starts Python once, and ▶ runs the main file in a fresh module __main__; the project's files are loaded again.
  • The standard library's modules stay loaded: random continues its sequence instead of starting anew, and what a program changes in such a module still holds at the next ▶.
  • After ▶, the >>> line goes on with the file's variables and functions, like python -i main.py.
  • sys.argv is [''], __file__ is /main.py, sys.platform is emscripten. The time zone is the browser's, the locale en_US.UTF-8.

Error messages

  • A traceback looks as in CPython. The project's files are named main.py, without a folder; the standard library /lib/python312.zip/….
  • For some common mistakes a short hint below Python's message says what the cause could be. Python's own message stays as it is.
  • Error numbers are Emscripten's: a missing file gives [Errno 44] instead of [Errno 2].

Turtle graphics

  • Instead of turtle there is the module gturtle with makeTurtle(), forward(), backward(), left(), right(), penUp(), penDown(), setPenColor(), setLineWidth() and clear().
  • The turtle doesn't draw stroke by stroke: the picture appears when the program has finished (in the visualizer step by step).

Tests

  • «Tests» runs the examples in the docstrings as python -m doctest main.py does: the file is loaded as a module, a block if __name__ == "__main__": doesn't run.
  • Unlike doctest, the value counts when the expected text and the output are each one Python literal (number, string, list, tuple, dictionary, set, True/False/None): 4 matches 4.0, "+" matches '+', [1,2,3] matches [1, 2, 3]. Everything else (several lines, errors, examples with options such as ELLIPSIS) doctest compares as text, as usual.
  • Where switched on, the report also names the lines no example executed.

The visualizer

The visualizer runs the program in an interpreter of its own, expression by expression. The result is the same as in CPython; which steps it shows is glpython's choice:

  • A name in xs[1] is no step of its own: xs[1] becomes the element in one step.
  • A list, tuple, set or dictionary in brackets ([…], (…), {…}) has no step of its own, unless its value reads differently from its text; nor does a negative number such as -3.
  • Values are shown as one writes them: types as int, not <class 'int'>. Long values are abbreviated ([1, 2, 3, 4, 5, …, 100]); a click shows them in full. What the program prints keeps Python's repr.
  • What the visualizer doesn't know in detail runs in a single step.
  • It shows at most 6000 steps and 200 nested calls; beyond that RecursionError: maximum interpreted recursion depth exceeded (CPython allows about 1000).
  • Visualizing an input of the console means running the session again. If something else comes out (e.g. with random numbers) or it needs input(), a note appears instead of the visualization.
