Differences between glpython and CPython

glpython runs Python 3.12 in the browser, with Pyodide 0.26: CPython compiled to WebAssembly. The language and the standard library are the same. For the language itself: the Python tutorial and the language reference.

Additions

Visualizer

Shows a program expression by expression, in an interpreter of its own. The result is the same as in CPython; glpython decides which steps it shows:

  • xs[1] is one step, straight to the element (no step for xs).
  • […], (…), {…} and negative numbers like -3 get no step of their own, unless their value reads differently from the text.
  • Values are shown as one writes them (int, not <class 'int'>); long values are cut, a click shows them in full.
  • What it doesn't know in detail runs as one step.
  • At most 6000 steps and 200 nested calls, then RecursionError: maximum interpreted recursion depth exceeded.
  • Visualizing a console input replays the session; if something comes out differently (random numbers) or it needs input(), a note is shown instead.

Tests

  • «Tests» runs the examples in the docstrings like python -m doctest main.py.
  • When the expected text and the output are each one literal, the value counts: 4 matches 4.0, "+" matches '+', [1,2,3] matches [1, 2, 3]. Otherwise doctest compares text.
  • Where switched on, the report names the lines no example ran (only when all examples pass).

More

  • Below Python's error message, common mistakes get a short hint; the message itself is unchanged.
  • The module gturtle for turtle graphics: makeTurtle(), forward(), backward(), left(), right(), penUp(), penDown(), setPenColor(), setLineWidth(), clear().
  • The input line >>> works on with the file's names after ▶, like python -i main.py.

Missing

  • Network: urllib.request has no https, socket reaches nothing.
  • Threads and processes: threading, subprocess, multiprocessing, os.fork() raise an error.
  • Packages: no pip, only the standard library (no numpy, no requests).
  • Standard modules: tkinter, turtle, sqlite3, ssl, lzma, curses, readline, dbm, venv, ensurepip, idlelib.
  • asyncio.run() and webbrowser.
  • input() in an embedded editor (e.g. in a course), often: RuntimeError: input() is not available here; help(), breakpoint() and sys.stdin don't work there either. In the IDE input() works.
  • Written files aren't kept: what a program writes stays in memory until Python restarts; it doesn't appear in the editor. A project file has the editor's text again at the next ▶.

Differences

▶ doesn't start a new session

The first ▶ starts Python. Every later ▶ runs the main file in a fresh __main__, but in the same Python: loaded standard modules keep their state (random continues its sequence), and the input line works on with the file's names, like python -i main.py. Every ▶ loads the project's files again. Stop and «Restart Python» (⋮) start a new Python.

Files

  • The project's files are in / (/main.py); import hilfe finds hilfe.py.
  • ▶ runs the main file, not the file in the editor; the console names it.

Output and input

  • Output appears line by line: print(…, end="") only with the next line.
  • sys.stdout and sys.stderr appear mixed in the console.
  • input() asks in the console: the line >>> becomes the input line; prompt and answer then appear as one line.
  • Stop ends Python entirely, without KeyboardInterrupt; the input line then knows nothing from before. While the program waits for input(), Stop gives EOFError.

Environment and error messages

  • sys.argv is [''], __file__ is /main.py, sys.platform is emscripten; the time zone is the browser's.
  • In a traceback the project's files are named main.py, without a folder.
  • Error numbers are Emscripten's: a missing file is [Errno 44], not [Errno 2].

Turtle graphics

  • The picture appears when the program has finished, not stroke by stroke (in the visualizer step by step).

Known bugs

Not intended; they will be fixed.

  • A last line without a line end (print("x", end="") at the end) appears only at the next ▶, before its output.
  • Spaces and empty lines at the start of the output disappear when the program ends without an error; empty lines at the end always.
  • The working directory is /home/pyodide, the files are in /: open("daten.txt") doesn't find a project file, open("/daten.txt") does.
  • sys.exit() and exit() show SystemExit in the console instead of ending silently.
